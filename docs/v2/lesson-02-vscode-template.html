The 5-file pattern

Every mechanism in this project follows the same shape. Open the arm/ folder in the Explorer panel (Ctrl+Shift+E → src/main/java/frc/robot/subsystems/arm/) and find these five files:

ArmIO.java

The interface. Defines what the subsystem can do and what it can read — without any hardware details.

Inputs are declared here with @AutoLog. The subsystem only talks to this interface, never to hardware directly.

ArmIOXRP.java

The real hardware implementation. Talks to the actual XRP servo.

Implements ArmIO. Only used when Constants.currentMode == REAL.

ArmIOSim.java

The simulation implementation. Fakes the hardware so code runs on your laptop without a robot.

Implements ArmIO. Used when Constants.currentMode == SIM.

Arm.java

The subsystem. Contains all the logic — clamping, state tracking, commands. Calls io.updateInputs() every loop.

Never touches hardware directly. Swapping XRP ↔ Sim requires zero changes here.

ArmConstants.java

All fixed values for this subsystem — angle limits, speeds, servo channel.

Change a hardware pin or a limit once here. Everything else updates automatically.

Read before you build

Spend 5 minutes reading ArmIO.java and Arm.java. You're about to build Scoop using the same shape. The Arm is your reference — copy from it when you get stuck.

How it fits together

RobotContainer.java is where subsystems are wired up. Open it and find where Arm is instantiated:

arm = new Arm(
    switch (Constants.currentMode) {
        case REAL  -> new ArmIOXRP();
        case SIM   -> new ArmIOSim();
        default    -> new ArmIO() {};
    }
);

The subsystem receives its IO implementation here. Changing currentMode in Constants.java swaps the hardware layer — the subsystem code never changes. You'll wire Scoop and Elevator the same way.

Constants.currentMode must be SIM for today

Open Constants.java and confirm: public static final RobotMode currentMode = RobotMode.SIM;

You're building on a laptop without a robot — SIM mode is required.

How snippets work

In a new .java file, type the snippet trigger and press Tab. The snippet expands into a full class template. Tab through the placeholders to fill in names — VS Code updates all occurrences at once.

Robot.java — compose poses
▶

Three things in robotPeriodic(): shift the scoop's 2D root with the elevator height, compose the scoop's 3D pose onto the elevator's using Transform3d, then log all three.

Robot.java — new import
import edu.wpi.first.math.geometry.Pose3d;
import edu.wpi.first.math.geometry.Transform3d;
Robot.java — robotPeriodic()
    CommandScheduler.getInstance().run();

    robotContainer.getScoop().setBaseHeightMeters(robotContainer.getElevator().getPositionMeters());

    Logger.recordOutput("FinalComponentPoses", new Pose3d[] {
      robotContainer.getArm().getComponentPose(),
      robotContainer.getScoop().getComponentPose()
    });
    Pose3d elevatorPose = robotContainer.getElevator().getComponentPose();
    Pose3d scoopLocalPose = robotContainer.getScoop().getComponentPose();
    Pose3d scoopPose = elevatorPose.transformBy(
        new Transform3d(scoopLocalPose.getTranslation(), scoopLocalPose.getRotation()));

    Logger.recordOutput("FinalComponentPoses", new Pose3d[] {
      robotContainer.getArm().getComponentPose(),
      elevatorPose,
      scoopPose
    });
  }
